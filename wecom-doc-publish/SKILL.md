# 企微文档发布

本地 Markdown 是正文来源。用户只要求写文档时先保存到本地；明确要求发布或更新后执行同步，并在发布成功后通知已配置且已授权的群，除非用户明确要求不通知。项目、文件、文档类型和 TAPD 能从上下文确定时，直接执行，不重复询问发布或群通知许可。

## 安装与配置

首次使用或缺少 config.json 时，读 [安装与配置](references/安装与配置.md)。SKILL_DIR 指本次加载技能的安装目录绝对路径；命令中替换为该路径。该目录的 config.json 可链接到独立的本机私有配置，不要复制其他人的配置、状态或登录信息。

常规发布与关联人员解析统一使用 `SKILL_DIR/config.json` 指向的本机通用配置，建议固定保存在 `~/.config/wecom-doc-publish/config.json`，不要放在任务临时目录。新增已核实的人员映射补到通用配置，供后续需求复用；确需任务配置时从通用配置派生，保留通用映射和原发布状态路径，不把临时配置替换为默认入口。

| 用途 | 配置与规则 |
| --- | --- |
| 关联人员 @ | 使用通用 `tapd_mentions.userids`，其次使用已确认的 `resolved_members`；按真实 userid 匹配与去重 |
| 文档链接阅读 | 显式设置 `link_access=corp_read`：企业内持链接只读，企业外禁止通过链接加入 |
| 文档指定成员授权 | 按项目维护者、阅读者及 `member_lookup_excluded` 处理；不从 @ 名单新增成员授权 |

群通知 key 由配置中 webhook_key_env 指定的环境变量提供，默认示例为 WECOM_WEBHOOK_KEY。配置只保存变量名，不保存 key 或完整 Webhook。不要打印或复述变量值；缺少变量时分别报告文档发布和通知状态。不得为测试环境变量而向真实群发送消息。

## 发布与更新

```text
python3 SKILL_DIR/shared_publisher.py --config SKILL_DIR/config.json publish --project api --tapd TAPD原链接 --file Markdown绝对路径 --kind 对接与测试说明 --execute
```

同一份正文涉及 Admin 时加 `--also-project admin`；预览时省略 `--execute`。使用 shared_publisher.py，不能换成会全量重写独立目录的旧入口。

### TAPD 交付联动

已启用 `tapd_sync` 时，先读 [TAPD 交付与节点](references/TAPD交付与节点.md)。代理从本次正文、实际改动和分支自动生成交付 JSON，发布命令追加 `--tapd-handoff 清单绝对路径`；不要让用户手填技术清单。发布成功后自动评论文档链接及适用的 SQL、菜单交接，并填写有依据的开发字段。同版本不重复评论，跨项目共用同一正文与一份评论；这不构成发布新内容的授权。

实际工时只使用用户提供或已确认的记录；已有非空字段冲突不默认覆盖。分别报告企微发布、群通知、TAPD 评论、字段回填的结果；部分失败不能说全部完成。评论或字段 `unknown/sending` 时只读回核对，不能清空状态或盲目重发。

发布文档不完成开发节点。用户明确要求完成某个节点后，核对交付证据、当前节点和必填项，用独立 `tapd_cli.py complete-step` 先预览再执行；缺少真实必填值只暂停受影响节点。不直接改需求 `status`，也不自动完成后续节点。

### 提醒 TAPD 关联人员

只有需求标题、未提供 TAPD 链接时，先用已授权的读取工具在已核实项目中检索，核对标题、当前任务与直接父子关系；确认唯一对应对象后再解析人员。不能把“上下文没有链接”直接当作“没有关联”。多个合理候选只暂停关联确认，不猜测对象或遍历无关项目。

用户要求本次发布且需要群通知时，有真实 TAPD 关联就按 [TAPD 关联人员提醒](references/TAPD关联人员提醒.md) 先运行只读 `tapd_mentions.py`，读取本任务、直接父需求及同层子任务的前端、后端、测试人员。将返回的 `mention_markdown` 加入本次 `--notification-file`，让真实 @ 与文档链接在同一条持久通知中发送；普通说明文档也采用此步骤。使用已确认的企微 userid，不把 TAPD 用户名或“@姓名”当作真实提醒。

部分人员无法唯一匹配时，已匹配人员正常加入通知，交付结果列出未匹配及跳过的人员；不声称已通知全部人员。无 TAPD 关联时不猜测人员；明确不通知时不执行此步骤。正文未变沿用“不重复通知”，不因负责人变化补发历史通知；本地映射维护也不发送消息。

### 根据文档用途自动选择通知模板

用户只说“发布到企微”时，也应先读本地正文，结合标题、主要读者和用途自行选模板，不要求用户再次指定类型：

| 主要用途 | 使用模板 | 通知分组 |
| --- | --- | --- |
| 同一需求同时发布测试交接、前端联调两份独立文档 | [双文档合并通知模板](references/双文档合并通知模板.md) | 交付信息、文档入口、上线依赖、前端联调重点、测试重点、执行顺序；合并为一条 |
| 交给测试执行用例、验证功能与回归，交接已验证结果及待测项 | [测试交接通知模板](references/测试交接通知模板.md) | 交付信息、上线依赖、测试重点、上线顺序 |
| 交给前端按接口契约接入页面，说明参数/字段/状态、环境及接入步骤 | [前端联调通知模板](references/前端联调通知模板.md) | 联调信息、接口与依赖、联调重点、联调顺序 |
| 设计、排查或其他普通说明 | 既有简短通知 | 项目、正文与相关目录链接 |

双文档合并规则优先于单文档模板：两篇分别保留，通知使用加粗分组、少量 emoji、短列表和两个明确入口；不拼成长段落、不连续运行两次自动通知的单文档发布。先读双文档模板中的发布与去重约束。单份前端联调文档含测试用例时仍按前端用途选择；单份混合正文按主要用途选一套并补充必要的另一类重点。

按所选模板，从本地正文、实际分支及已核实环境填好本次通知Markdown，不编造接口、字段、部署、自验或上线结论；未知信息写“待确认”。仅保留一个 `{document_url}` 链接占位符，在发布命令加 `--notification-file 通知绝对路径`，正文及目录成功后由同一持久事件发送，不能先发旧格式再补发。没有真实TAPD链接时，不伪造需求关联；复用现有项目目录和底层发布能力，通知同样通过 `group_notify.markdown_payload()` 与持久事件发送。通知内容不超过4096 UTF-8字节，过长时保留摘要、细节指向正文。

- 使用配置中的固定共享目录，先读取再局部追加缺失链接，保留他人的内容。同一 TAPD 需求复用唯一入口、按项目分组；已启用 TAPD 联动且用户要求本次发布时，按上述规则同步。没有真实 TAPD 关联时，不伪造对象，沿用无关联的正文发布路径并说明未同步 TAPD。
- 更新自己登记的同一份源文件沿用原链接。文件改名、移动或接管他人的文档时先核实映射，不能据同名文件覆盖他人的正文。
- 图片先上传，Mermaid 先转 PNG；失败就报告，不能把代码块当流程图。未发布的本地 Markdown 参考只显示文件名，不递归发布。
- 正文全量更新会重建正文块，不能保证行内评论保留。有保留讨论要求时说明限制并选择局部修改。
- 首次发布和内容更新成功后，工具自动通知已配置且已授权的群，内容不变不发。不能在工具外重复通知，不能因通知失败重建文档；设置 key 本身不会发消息。
- 多个需求候选或远端写入结果不确定时停止核实；不猜测、不清空状态或盲目重试。通知 unknown/sending 时由用户在群里核实；明确未发送的最近事件才能按要求 notify-retry。
- 文档指定成员授权按配置排除的成员不查询、不同步，也不列为权限待处理。关联人员已有通用映射时仍正常 @，不能因其位于权限排除名单而跳过；没有映射的排除成员不自动查通讯录，需用户明确授权核实后补通用映射。@ 不触发文档成员授权，权限排除也不撤销企业内持链接阅读。分别核实正文发布、通知送达和成员客户端访问。

## 阅读权限

本技能默认发布规则为 `link_access=corp_read`：能看到文档链接的企业成员都可只读，企业外禁止通过链接加入，保留指定编辑者。发布前确认实际配置显式设置该值；程序为兼容旧配置仍将缺省值解释为 `members`（指定成员），不能把程序缺省值当作本技能的默认规则。用户明确要求更窄范围时遵从。关联人员 @ 映射和文档指定成员排除名单均不限制企业内链接阅读，也不授予企业内编辑或公开访问。应用创建的文档需通过接口设置权限，不能依靠客户端申请。

新建或更新本机管理的文档会自动应用该配置。用户要求迁移现有规则时：

```text
python3 SKILL_DIR/shared_publisher.py --config SKILL_DIR/config.json sync-rules --include-shared --execute
```

只作用于本机已登记文档；include-shared 明确包含接入的共享目录/需求入口，普通发布不修改其他作者的目录权限。迁移不改正文、不查通讯录、不发群通知，也不撤销单独授予的成员权限。企业内阅读不代表拥有共享目录编辑权；指定发布者编辑权需创建应用通过成员接口另行授予。

## 读取与维护

```text
python3 SKILL_DIR/shared_publisher.py --config SKILL_DIR/config.json read --url 企微文档链接
python3 SKILL_DIR/shared_publisher.py --config SKILL_DIR/config.json status
```

用户明确要求补齐已确认名单时才执行 sync-members。接口成功不能代替其他同事客户端验收。配置、发布状态、私密文件和环境变量值均不进入 Git、分享包或回复。
