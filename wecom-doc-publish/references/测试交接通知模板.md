# 测试交接通知模板

用户已确认：今后发布测试交接文档时，群通知使用下面的结构。仅约定通知样式，不代表预先授权发布或发送未来文档；继续以当次用户请求为准。设计、排查和普通说明文档保留原通知格式。

从本地正文和真实代码提取信息，将所有中文占位内容替换为已核实事实；无法确认的依赖写“待确认”，不编造SQL、定时任务或上线结论。通知应便于手机阅读，采用加粗小标题、少量emoji和短列表，不使用表格。总长不超过4096 UTF-8字节。

```markdown
**📣 需求发布｜〈需求名称〉**

〈一句话说明目标与用户可见变化〉

**📦 交付信息**
- **涉及项目：** 〈实际项目〉
- **代码分支：** 〈各项目实际分支〉
- **交接文档：** [〈交接文档名称〉]({document_url})
- **当前状态：** 〈开发自验、测试验收、上线状态分别说明〉

**⚙️ 上线依赖**
- **SQL：** 〈无 / SQL文件及执行要求 / 待确认〉
- **定时任务：** 〈复用 / 新增 / 调整及注意事项〉
- **其他影响：** 〈跨项目部署、公共组件等真实影响；无则省略〉

**🧪 测试重点**
1. 〈核心正例〉
2. 〈筛选、状态或边界场景〉
3. 〈回归及页面链路〉

〈已验证范围与仍待验收项，避免将局部自验写成全量验收〉

**🚀 上线顺序**
1. 〈环境及依赖准备〉
2. 〈按依赖顺序部署〉
3. 〈数据处理及验收〉
```

将填好的本次通知保存到本地Markdown文件，仅保留一个 `{document_url}`，发布器会替换为真实正文链接。有真实TAPD链接时使用既有共享发布命令，并加 `--notification-file 通知绝对路径`；没有TAPD不伪造关联，复用已配置项目目录及底层发布能力，使用同一个 `group_notify.markdown_payload()` 生成并登记持久通知事件。

自定义通知仍遵守正文及目录成功后发送、同一内容不重复通知、sending/unknown不盲重发的规则。不能先自动发旧通知再补发模板通知；通知未发送时只补发当前有效事件，不重建文档。正文、目录和通知分别读回或核实，接口sent不等于每名同事客户端已读。
