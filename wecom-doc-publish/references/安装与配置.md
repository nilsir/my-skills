# 安装与配置

技能需要 Python 3.9+、wecom-cli、Mermaid CLI 和 Chrome。已验证 macOS；脚本使用 fcntl，不支持原生 Windows。

## 安装

将整个 wecom-doc-publish 文件夹放进 Codex 技能目录（如 ~/.codex/skills/wecom-doc-publish）。从仓库复制或链接代码均可；升级时保留自己的 config.json、state.json 和 private/，不要删除整个已安装目录。不要复制他人的登录信息、发布状态或密钥。

缺少依赖时可安装已验证版本：

```bash
npm install -g @wecom/cli@1.3.4
PUPPETEER_SKIP_DOWNLOAD=1 npm install -g @mermaid-js/mermaid-cli@12.0.0
wecom-cli auth init
wecom-cli auth show --status
```

本人扫码授权，且需要读取/编辑共享目录的能力；已有授权时不重复初始化。

## 本机配置

将 config.example.json 复制到本机固定私密目录（建议 `~/.config/wecom-doc-publish/config.json`），再让 `SKILL_DIR/config.json` 链接到该通用配置；常规发布、关联人员解析均使用这个入口。配置和 state.json 不进入 Git，不存放在易清理的任务临时目录。

- publisher_label：自己的显示姓名。
- projects：本机 API/Admin/Mall 仓库绝对路径，以及已经确认的维护者和阅读者。
- shared_catalog：现有根目录和三个项目目录的真实企微智能文档链接；不能重新建立另一套目录。
- state_path：本机发布记录路径；迁移安装时沿用已有路径或完整迁移已有记录，保留正文映射及已发送通知状态，不新建空状态覆盖历史。
- cli_path、mermaid_cli、chrome_path：本机可执行文件路径。
- link_access：示例与本技能的默认发布规则均为 corp_read，发布前显式配置：企业内持链接只读、企业外禁止通过链接加入，保留指定编辑者。用户明确要求更窄范围时遵从。程序兼容旧配置时缺省为 members，不能省略此项后误用指定成员阅读。每份正文/目录分别设置，不能假设继承。
- tapd_mentions.userids：通用的“完整 TAPD 昵称 → 已核实企微 userid”映射；新增映射局部补到这里，供其他需求复用。已有 resolved_members 可用于精确匹配；两类映射都不代表文档成员授权。
- member_lookup_excluded：继续排除对应人员的文档指定成员查询与授权，不列为权限待处理；已有通用映射的关联人员仍可 @。没有映射的排除成员不自动查询，用户明确授权核实后才补映射；不因此移除权限排除项。

已有独立本机配置时，可将安装目录的 config.json 链接到该文件；程序按实际配置文件所在位置解析相对状态路径。维护者的共享目录编辑权需要由创建应用通过成员接口授予，阅读规则不授予编辑权。

确需任务配置时从通用配置派生，保留人员映射和原状态路径；新确认的账号仍回填通用配置。不要用仅含本需求映射的临时配置替换通用入口，也不要把 @ 人员写入文档维护者或阅读者名单。目录建议 0700，私密配置与状态文件建议 0600。

## TAPD 个人访问令牌

联动可选，示例默认关闭。用户要求接入后，将 `tapd_sync.enabled` 设为 true，`credentials_path` 指向本机私密 JSON 文件（相对路径按配置文件所在位置解析）。文件只含 `access_token`，不需要企业 API 账号和密码。建议目录权限 0700、文件权限 0600；令牌不进入仓库、命令参数或聊天。

安装时必须包含 `tapd_client.py`、`tapd_handoff.py`、`tapd_cli.py`、`tapd_mentions.py`。符号链接安装者需为四个文件补齐链接，保留原 config、state 和 private。设置密钥不触发评论、消息或节点变更。先按 [TAPD 交付与节点](TAPD交付与节点.md) 运行只读 inspect；关联人员解析按 [TAPD 关联人员提醒](TAPD关联人员提醒.md) 验证。只读成功不证明写权限或实际提醒送达可用。

## 用环境变量提供群机器人 key

config.json 只保存变量名：

```json
{
  "group_notification": {
    "enabled": true,
    "webhook_key_env": "WECOM_WEBHOOK_KEY"
  }
}
```

WECOM_WEBHOOK_KEY 的值只填 Webhook 地址中 key= 后面的值，不填完整 URL。程序固定请求企微官方群机器人地址。

在运行发布命令的同一进程环境中设置它。例如在自己的终端中隐藏输入（不要把实际 key 写进命令或聊天）：

```bash
read -r -s WECOM_WEBHOOK_KEY
export WECOM_WEBHOOK_KEY
```

输入 key 后按回车，再在同一终端运行发布命令。也可以把 .env.example 复制为本机 .env，填值后以受信任的本机 shell 加载；.env 被 Git 忽略，程序不会自动加载它。桌面 Codex 不一定继承后来在另一个终端设置的变量，应在实际执行发布命令的环境注入，不能仅凭终端已 export 就宣称已配置。

配置允许自定义 webhook_key_env 变量名。变量已设置但为空或格式错误时停止该次通知，不回退到旧群。变量未设置且存在旧版 webhook_file 时兼容原有权限受限的私密文件；新安装无需该字段。私密文件不移入仓库。不需要群通知时把 enabled 设为 false。

缺少 key 时文档仍可发布，通知状态为 not_configured；不会补发配置前的历史消息，也不能为验证配置擅自发送测试消息。用户授权的真实首次发布需核对接口结果，再在群客户端确认收到。

## 迁移现有阅读规则

用户已确认范围后，从安装目录执行：

```bash
python3 shared_publisher.py --config config.json sync-rules --include-shared --execute
```

只迁移本机登记的目录、需求入口和正文；不改正文、不查通讯录、不发群通知。省略 --execute 先预览。其他作者的未登记正文需由原发布者处理，不声称覆盖全部文档。

## 本地验证

```bash
python3 -m unittest discover -s wecom-doc-publish -q
```

在仓库根目录运行；测试使用模拟企微服务，不向真实群发送消息。测试通过不代表真实授权、群送达或同事访问已经验收。
