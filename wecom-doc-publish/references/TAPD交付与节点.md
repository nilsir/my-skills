# TAPD 交付与节点

适用：用户已经要求企微发布后同步关联 TAPD，或明确要求完成某个开发节点。本技能不会因为有密钥就补发历史文档或推进历史任务。

## 发布前准备

1. 从用户链接和当前任务文档确认目标需求。支持详情链接与 `my/work?dialog_preview_id=story_...`；对象标题含“任务”不代表使用 tasks 接口。当前实现支持 story，对其他对象不猜测。
2. 读取实际代码改动、分支、SQL 和菜单配置，将交付说明补充到正文。跨项目只用同一份正文，发布以主项目为 `--project`，其他项目用 `--also-project`。
3. 由代理生成以下 JSON 清单，不让用户手工填写。ID 使用字符串。无 SQL/菜单时写空列表；没有依据的字段省略，不能用“无”掩盖未知。

```json
{
  "workspace_id": "44667425",
  "story_id": "1144667425001026696",
  "summary": "按本次真实改动编写交付摘要",
  "verification": "逐项说明已验证结果与未完成验收",
  "fields": {
    "涉及端口": ["API", "Admin"],
    "需求关联系统": ["用户中心"],
    "代码分支": "api:feature-example; admin:feature-example"
  },
  "sql": [],
  "menus": []
}
```

上例仅演示结构，不能原样用于这条需求的真实交付。字段来自目标项目的实时元数据，不能硬编码 `custom_field_*` 编号。各仓真实分支独立核对；Go 服务按实际涉及的端口填写。现有非空值不一致会报告冲突，不覆盖同事或用户已填内容。

SQL 条目包含 `sql`（完整语句）、`environment`、`status`、`notes`（执行顺序、前置检查及回滚说明）。菜单条目包含 `name`、`parent`、`route`、`permissions`、`status`。所有条目字段均为非空字符串。仅使用用户授权交付的 SQL，删除其中的凭据或明文个人信息。有 SQL/菜单条目时，工具自动将“需要执行SQL”/“需配置菜单”补入发布关联操作；其他发布依赖由代理依据实际变更填入 `fields.发布关联操作` 的列表。

`实际工时（人/日）` 只接受用户实际填报或已确认工时，单位为人日；缺少时不填写，不使用 AI 运行时间或估计值。代码注释、提测计划和 SQL 文件存在不证明已经部署、执行或验收。

## 发布命令

```text
python3 SKILL_DIR/shared_publisher.py --config SKILL_DIR/config.json publish --project api --also-project admin --tapd TAPD原链接 --file 正文绝对路径 --kind 测试交接 --notification-file 通知绝对路径 --tapd-handoff 清单绝对路径 --execute
```

先省略 `--execute` 预览，校验目标、清单和字段。预览会只读 TAPD，不发布文档、评论或字段。用户已明确要求本次发布且预览通过时直接执行，无需再次确认。没有 TAPD 关联时不要随便选当前待办当目标，继续既有无关联发布路径。

真实发布后逐项检查返回值：企微 `published/unchanged`、群通知结果、`tapd_sync.comment`、`tapd_sync.fields`、`tapd_sync.field_conflicts`；TAPD 总状态只有 `verified` 才表示本次评论和所填字段均核对成功。`partial` 时交付已完成部分并说明冲突/失败，不能重复发送群消息。评论永远不会触发节点完成。

同版本重试使用原正文、原清单、原主项目，工具复用原文档、评论和持久事件。新版本追加评论保留交付历史，不覆盖其他人的评论。当前仅有本机文件锁，没有跨机器原子去重承诺。

## 超时与恢复

评论 POST 前保存 `sending`，响应丢失保存 `unknown`。下次同版本同步会分页读取同一需求的评论，按作者与唯一版本标识核对；找到一条则恢复，找不到也不自动重发。字段请求未知时只核对目标值，不重复写入。无法确认时报告具体未确认阶段，由用户在 TAPD 核实；不得删除状态来解除保护。明确拒绝、修复权限或参数后可再次执行同一交付。

企微群消息的 `notify-retry` 仅适用于群通知，不能用来重试 TAPD。TAPD 失败不重建文档；重新运行同版本发布不会重复发送已发送通知。

## 独立检查与节点完成

```text
python3 SKILL_DIR/tapd_cli.py --credentials 本机凭据路径 inspect --tapd TAPD详情链接
```

预览链接不含项目 ID 时追加 `--workspace 已核实项目ID`。输出包含五个交付字段的配置及节点状态，明确 `write_permissions_verified=false`；不输出令牌、联系人信息或原始认证响应。

只有用户明确要求完成目标节点时，整理已有的完成证据到本机文本文件，先预览：

```text
python3 SKILL_DIR/tapd_cli.py --credentials 本机凭据路径 complete-step --tapd TAPD详情链接 --step 开发中 --evidence-file 已有完成证据绝对路径
```

依据实际工作流指定唯一中文名称或内部节点名，不自动选“下一个”。核对目标节点处于进行中、前置开发与验证已完成、所有必填信息具备；预览为 `planned` 才加 `--execute` 执行。用户明确指令已构成该节点授权，不重复询问“是否继续”。若工时属于必填且尚缺真实值，询问真实工时并停止该节点；可继续无依赖的评论和字段工作。

完成接口不传需求 `status`，避免重置并行流程；每次仅完成一个明确指定节点，不顺带完成其后继节点。操作记录默认保存在凭据文件旁的 `node-state.json`，可通过全局 `--state` 指定其他私密位置。节点请求结果未知后再次执行只读回，不重发；只在读回目标节点已完成后报告成功。

本机真实只读通过与离线测试不代表真实写权限、企微送达或 TAPD 端到端写入已验收；首次真实授权交付应分别记录接口与读回证据。
