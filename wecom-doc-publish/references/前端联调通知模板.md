# 前端联调通知模板

若同时发布独立的测试交接文档，优先使用[双文档合并通知模板](双文档合并通知模板.md)，两份文档共用一条通知；不要分别执行两次自动通知。

当本地文档主要用于前端根据接口契约接入页面时使用；文档即使包含测试用例，也不因此改用测试交接模板。用户要求发布或更新到企微时，自动采用本模板并通知已配置群，无需重复询问；只要求编写文档或明确不通知时遵从相应边界。

从本地正文、代码和真实环境中提取信息。按实际项目填写分支、接口及联调依赖，不假设本地分支已部署，不把后端自验写成前端已联调。无法核实的信息写“待确认”，与本次无关的可选项省略，不补造必填参数、错误码或配置。鉴权只描述要求，不写入令牌、密码或个人信息。

通知采用加粗小标题、少量emoji和短列表，便于手机阅读；不使用表格。字段明细和完整请求响应留在正文，通知总长不超过4096 UTF-8字节。

```markdown
**🔌 前端联调｜〈需求名称〉**

〈一句话说明本次页面或交互变化，以及前端需要接入的能力〉

**📦 联调信息**
- **涉及项目：** 〈前端、API、Admin、Mall中的实际项目〉
- **代码分支：** 〈已核实的各项目分支；未提供的前端分支不编造〉
- **联调环境：** 〈可用环境、域名及后端部署状态；未知写待确认〉
- **联调文档：** [〈联调文档名称〉]({document_url})
- **当前状态：** 〈后端自验、环境就绪及前端联调进度分别说明〉

**🧩 接口与依赖**
- **涉及接口：** 〈请求方法及路径摘要，多个接口的明细见正文〉
- **契约变化：** 〈新增/调整的参数、响应字段或状态及兼容要求〉
- **前置依赖：** 〈鉴权、配置、测试数据或跨项目版本；无则写无〉

**🧪 联调重点**
1. 〈主流程与关键交互〉
2. 〈本次涉及的字段类型、状态或筛选/分页等边界〉
3. 〈本次涉及的空态、异常态及原功能回归〉

〈后端已验证的范围，以及仍需前端确认的页面表现或链路〉

**🚀 联调顺序**
1. 确认目标环境、后端版本及所需测试数据可用。
2. 按文档完成接口参数、响应字段与页面状态接入。
3. 完成主流程和适用边界回归，反馈实际环境、版本及复现信息。
```

替换所有中文占位内容后保存本次通知Markdown，仅保留一个 `{document_url}`。有真实TAPD链接时通过既有共享发布命令的 `--notification-file` 参数传入；无TAPD时复用已配置项目目录及底层发布能力，不虚构需求关联。使用 `group_notify.markdown_payload()` 将占位符替换为真实正文链接并登记持久事件。

正文与目录完成后只发送一次；不因模板更新补发历史文档，不因通知失败重建正文。保持原有去重和未知发送结果处理规则，正文发布、通知接口结果与同事实际访问分别核实。
