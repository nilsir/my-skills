# TAPD 关联人员提醒

用于已经获准的本次企微发布：从对应 TAPD 任务取前端、后端、测试人员，在原群通知中真实 @。本步骤不授予新内容发布、历史补发、修改文档权限或推进 TAPD 节点的权限。

## 读取人员与企微身份

生成通知文件前执行只读命令：

```text
python3 SKILL_DIR/tapd_mentions.py --config SKILL_DIR/config.json --tapd TAPD详情链接
```

预览链接没有项目 ID 时加 `--workspace 已确认项目ID`；不得用当前待办替代缺失的关联需求。命令只读取 TAPD、现有本机映射和企微通讯录，不发群消息，不回填字段，不改配置、状态或阅读权限。当前支持 story 对象；本环境“前端任务／后端任务／测试任务”实际就是子 story。无法识别的对象先核实，不改写链接以冒充 story。

逐文件符号链接安装的环境，需要将 `tapd_mentions.py` 与既有 TAPD 模块一并安装到 `SKILL_DIR`；不要复制或替换原有私密配置。

取人范围为当前任务的直接父需求及该父需求的直接子任务；没有父需求则读取当前需求及其直接子任务。不继续上溯更高层，也不遍历全项目。程序校验对象 ID、项目和父子关系；关系不一致、超过读取范围或数据格式异常会返回错误，避免把无关需求人员加入群提醒。

人员字段按真实元数据中的“前端人员”“后端人员”“测试人员”识别。明确标为前端、后端、测试的任务（包括没有父级的独立任务），会补充其开发人员和处理人；普通需求的处理人不自动当作开发人员。角色不明的开发人员标为“开发”，不猜前后端。专用字段为空不代表无人参与，应以子任务实际人员为准。

## 匹配规则

优先使用 `config.json` 中 `tapd_mentions.userids` 的明确映射，再使用配置及本机状态中的 `resolved_members` 精确映射；缺失时只接受企微通讯录中姓名或别名唯一精确匹配的结果。TAPD 昵称与企微姓名不同、同名多人或已有映射冲突时不猜测，也不将 TAPD 账号直接当作企微 userid。

需要补齐时，由用户或企微管理员确认对应账号，再仅修改本机私有配置。例如以下为虚构示例：

```json
{
  "tapd_mentions": {
    "userids": {
      "dev_demo": "wecom_demo_01",
      "qa_demo": "wecom_demo_02"
    }
  }
}
```

只补实际确认的条目，不整体覆盖配置；企微 userid 不从手机号或邮箱猜测。私有映射不纳入 Git 或分享包。已有 `member_lookup_excluded` 禁止自动查询；没有已确认映射时记为跳过，不绕过排除项，也不发起文档授权同步。

## 加入同一条通知

检查 JSON 的 `status`、`matched`、`unresolved` 和 `mention_markdown`。`read_only` 表示解析成功；`partial` 表示有人员未能匹配，退出码为 1，但其有效匹配仍可使用。`error` 不提供可用的提醒名单，不从不完整输出继续拼接。该状态与真实消息是否发送是两个独立结果。

将 `mention_markdown` 原样插入本次通知 Markdown 的正文链接前。可在模板原链接前插入，也可将原链接移到末尾；移动后删去原位置的链接，不能新增第二个占位符。例如：

```markdown
**相关人员：** <@wecom_demo_01> <@wecom_demo_02>

[查看对接与测试说明]({document_url})
```

这是企微 Markdown 的真实提醒语法；普通 `@姓名` 不等价。按 userid 去重，即使同一个人负责多项工作也只 @ 一次。不使用 `@all`。同一份正文仍只发原来的一条通知，不另外调用群机器人发送提醒。

通知由代理完成原有模板内容并加 `--notification-file` 传入现有发布器，保留唯一 `{document_url}`；用完整通知校验 4096 UTF-8 字节限制。长通知应缩短业务摘要，详细内容保留在文档，不能悄悄删除部分提醒对象。官方依据：[消息推送配置说明](https://developer.work.weixin.qq.com/document/path/99110)，`text` 和 `markdown` 支持 `<@userid>`，`markdown_v2` 不支持此扩展。

## 缺失与验收

- 有效映射加入通知，无法匹配者在本次交付结果报告，排除查询者标为跳过；不在群中公开账号问题或个人资料。
- 读取失败时报告“关联人员解析失败，本次未完成自动 @”；用户要求的正文发布可按原路径继续，但不能写成全部提醒成功。
- 没有 TAPD、用户明确不通知、正文内容不变时，分别沿用无关联发布、不通知、内容不变不发的既有规则；不补发提醒。
- 发布器返回发送成功只能说明接口接受。实际账号能否在该群被 @、成员是否收到提醒，需在下一次用户指定内容发布时验收。不得为了验证映射或语法向真实群发送测试消息。
